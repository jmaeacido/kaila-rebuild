## Authenticate the requester

Confirm the request comes from the account holder (signed-in Support case, or email matching the account plus challenge questions that do **not** demand a fresh reusable ID copy unless necessary).

## Request types

| Right | Handling |
| --- | --- |
| Access | Describe what is held; do not send raw ID/selfie by email. Prefer status summary; custodian preview only if proportionate. |
| Correction | Account profile fields via Settings; identity mismatches may require resubmission. |
| Withdrawal / objection | User may withdraw identity consent in-app (`DELETE` consent). Capability gates re-apply. |
| Erasure / blocking | Prefer `/account-deletion`. Identity objects purged; legal holds (when implemented) may block. |
| Portability | Export account profile JSON/summary via Support; raw identity images are not routinely ported. |
| Complaint | Inform of NPC complaint rights; acknowledge within a reasonable period. |

Log the request, decision, and completion date without storing image bytes in tickets.
